## 1. Executive Summary

This inventory examines the Sequelize models for **Group 1 (Auth & Users)** from the legacy backend codebase. The models reviewed include:
- `Role` (`app/src/models/role.model.ts`)
- `Profile` (`app/src/models/profile.model.ts`)
- `BaseTokenSchema` (`app/src/models/common/base-token-schema.ts`)
- `EmailVerificationToken` (`app/src/models/email-verification-token.model.ts`)
- `PasswordResetToken` (`app/src/models/password-reset-token.model.ts`)
- `RefreshToken` (`app/src/models/refresh-token.model.ts`)
- `LoginAudit` (`app/src/models/login-audit.model.ts`)
- *(Reference Core Entity)* `User` (`app/src/models/user.model.ts`)
- Associated relationships in `app/src/models/index.ts`

### Key Discrepancies vs. Migration Plan:
1. **`roles` table:**
   - **Plan Requirement (§6.3, §8.2):** Expects column `is_default BOOLEAN` with a partial unique index (`WHERE is_default = true`), plus audit timestamps (`created_at`, `updated_at`).
   - **Sequelize Reality:** Only contains `id`, `name` (`VARCHAR(40)`), and `description` (`VARCHAR(160)`). `is_default` does **not** exist. `timestamps: false` is configured (no `created_at` or `updated_at`).
   - **Impact:** A TypeORM migration must add `is_default`, `created_at`, `updated_at`, and the partial index without breaking existing roles.

2. **`refresh_tokens` table:**
   - **Plan Requirement (§7.9):** Specifies token family rotation with fields: `id`, `user_id`, `token_hash`, `token_family`, `expires_at`, `revoked_at`, `replaced_by_token_id`, `created_at`, `last_used_at`.
   - **Sequelize Reality:** Only contains `id`, `user_id`, `token_hash`, `expires_at`, `is_revoked BOOLEAN` (default `false`), `created_at`, `updated_at`.
   - **Impact:** `token_family`, `replaced_by_token_id`, `revoked_at`, and `last_used_at` do not exist in the legacy DB. To implement token family rotation in NestJS, a migration is required to add these columns.

3. **`profiles` table & 1:1 Relationship:**
   - **Plan Requirement (§8.1):** Enforces a strict 1:1 relation with `users`.
   - **Sequelize Reality:** `user_id` has `allowNull: false`, but lacks an explicit `UNIQUE` constraint or unique index at the model definition level. TypeORM must explicitly enforce `@OneToOne(() => User) @JoinColumn({ name: 'user_id' })` with a unique constraint.
   - **Foreign Keys:** `city_id` references `cities(id)`, and `favorite_cinema_id` (nullable) references `cinemas(id)`.
   - **Date Type:** `birth_date` is `DATEONLY` (PostgreSQL `DATE`, `YYYY-MM-DD`), not a full timestamp.

4. **Base Token Factory (`email_verification_tokens` & `password_reset_tokens`):**
   - Both models are generated dynamically via `createTokenModel(tableName)`.
   - Column schema: `id`, `user_id`, `token_hash`, `expires_at`, `used_at` (nullable), `created_at`, `updated_at`.
   - Model names generated by factory are pluralized PascalCase: `EmailVerificationTokens` and `PasswordResetTokens`.
   - No soft delete is used; consumption is tracked via `used_at IS NOT NULL` and expiration via `expires_at < NOW()`.

5. **`login_audits` table:**
   - `device_user_agent` is defined as `DataTypes.STRING` (PostgreSQL `VARCHAR(255)`). Standard User-Agent headers frequently exceed 255 characters. TypeORM should map this to `text` or ensure truncation.
   - `timestamps: true` creates `created_at` and `updated_at`, even though audit entries are immutable append-only records.

## 3. Detailed Model Inventories

### 3.1 Model: `Role`
- **File:** `app/src/models/role.model.ts`
- **Sequelize Model Name:** `Role`
- **Real Database Table Name (`tableName`):** `roles`
- **Sequelize Options:**
  - `timestamps: false` (Does **not** generate `createdAt` / `updatedAt`)
  - `underscored`: Not set (defaults to `false`)
  - `paranoid`: `false` (No `deleted_at`)

#### Columns
| Field in DB | Property Name | Sequelize Type | SQL Type | PK | AutoInc | Nullable | Default | Unique | Notes |
|---|---|---|---|---|---|---|---|---|---|
| `id` | `id` | `DataTypes.INTEGER` | `INTEGER` | **Yes** | **Yes** | No | Sequence | **Yes** | Primary Key |
| `name` | `name` | `DataTypes.STRING(40)` | `VARCHAR(40)` | No | No | No | None | **Yes** | Unique role name (`admin`, `cliente`) |
| `description` | `description` | `DataTypes.STRING(160)` | `VARCHAR(160)` | No | No | **Yes** | `null` | No | Optional human-readable description |

#### Foreign Keys and Constraints
- PK: `roles_pkey` on `id`
- Unique: `roles_name_key` on `name`

#### Indexes
- Primary Key index on `id`
- Unique index on `name`

#### Associations (from `app/src/models/index.ts`)
- `Role.hasMany(User, { foreignKey: 'role_id', as: 'users' })`
- Inverse: `User.belongsTo(Role, { foreignKey: 'role_id', as: 'role' })`

#### Discrepancies vs Migration Plan:
1. **Missing `is_default`:** Section 6.3 and 8.2 of the plan require `is_default: boolean` and a partial unique index `uq_roles_single_default ON roles (is_default) WHERE is_default = true`. This column does not exist in the current database.
2. **Missing Timestamps:** The plan lists `created_at` and `updated_at` as minimum columns for `roles`. In Sequelize, `timestamps: false` was explicitly defined.
3. **Migration Strategy:** The TypeORM migration must add `is_default BOOLEAN NOT NULL DEFAULT false`, `created_at TIMESTAMP WITH TIME ZONE DEFAULT now()`, and `updated_at TIMESTAMP WITH TIME ZONE DEFAULT now()`, followed by setting `is_default = true` on the `'cliente'` role, and then creating the partial unique index.

- `User.hasMany(RefreshToken, { foreignKey: 'user_id', as: 'refreshTokens' })`

#### Discrepancies vs Migration Plan:
1. **Critical Architecture Discrepancy (§7.9):**
   - The migration plan specifies:
     ```text
     Campos mínimos recomendados:
     id
     user_id
     token_hash
     token_family
     expires_at
     revoked_at
     replaced_by_token_id
     created_at
     last_used_at
     ```
   - In the legacy Sequelize model:
     - `token_family` is **MISSING**.
     - `revoked_at` is represented as a boolean flag `is_revoked` instead of a timestamp.
     - `replaced_by_token_id` is **MISSING**.
     - `last_used_at` is **MISSING**.
2. **Impact & Decision for TypeORM Entity:**
   - To support full token family reuse detection (Plan §7.9, §19), new columns must be added via a TypeORM migration:
     - `token_family VARCHAR(64) NULL`
     - `revoked_at TIMESTAMPTZ NULL` (can coexist with or supersede `is_revoked`)
     - `replaced_by_token_id INTEGER NULL REFERENCES refresh_tokens(id)`
     - `last_used_at TIMESTAMPTZ NULL`
   - During read-only transition phase, existing records only have `is_revoked` and `expires_at`.

## 4. Recommended Action Items for TypeORM Migration (Group 1)

1. **`roles` Migration:**
   - Add column `is_default` (`BOOLEAN DEFAULT false NOT NULL`).
   - Add columns `created_at` and `updated_at` (`TIMESTAMPTZ DEFAULT now() NOT NULL`).

   - To support token family rotation (§7.9), generate a migration adding:
     ```sql
     ALTER TABLE refresh_tokens
       ADD COLUMN token_family VARCHAR(64) NULL,

       ADD COLUMN revoked_at TIMESTAMPTZ NULL,
       ADD COLUMN last_used_at TIMESTAMPTZ NULL;
     ```
